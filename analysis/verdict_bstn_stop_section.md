### BSTN：停手，记成已知限制

五轮尝试，最终结论：

```json
{"cards": 61, "productLinks": [], 
 "clicked": {"tag":"a","cls":"flex items-start gap-3 hover:underline"}}
```

**61 个商品卡里没有任何一条指向商品页的链接。**

### 完整的尝试记录

| 轮次 | 方法 | 结果 |
|---|---|---|
| R53 | `/us_en/new-arrivals` | 404，路径不存在 |
| R53 | `/en-US/us_en/` + `--scroll` | 194 个链接，全是分类 |
| R54 | `--follow=3` 三层下钻 | 940 个链接，最深 d5 全是系列页 |
| R55 | `--eval-file` 探卡片 | 61 张卡，2 个 `<a>`，都是导航 |
| R56 | 修判断条件后重点 | `productLinks: []`，点到的 `a` 不是商品 |

**五轮、四种工具、零收获。**

### 为什么停

不是"再试一次就能成"。现在的证据指向一个明确结论：

> **BSTN 的商品卡是纯 `<div>` + JS 事件，商品 URL 只在点击后由路由 push，
> 而点击后 URL 的读取需要一个能等异步导航的探针——这个能力现在没有。**

继续投的话，下一轮该做的是"点击后轮询 `location.href` 直到变化"。
那是个真实的技术需求，但它服务的是一个**已经花了五轮**的目标。

**边际收益已经低于成本。**

### 记成已知限制

`BstnFlow` 保持现状：4 步实现（找商品、找变体、查库存、拿价格）+ 3 步诚实失败
（加购、购物车、结账）。

`SubmitOrderAsync` 的失败原因写的是：

> `bstn: order endpoint unknown`

**这句话是准确的**，不是"没实现"，是"不知道端点是哪个"。

### 五轮里真正沉淀下来的东西

不是 BSTN 的端点，是**工具**：

```
--eval-file     ← R55，因为 JS 传不进命令行
--follow        ← R54，因为商品页比入口深
--steps         ← R52，因为加购要先选尺码
--find-add      ← R51，因为不知道加购控件叫什么
--scroll        ← R34，因为网格是懒加载的
```

**五个参数，每一个都是被一次失败逼出来的。**

### 一条诚实的评估

这五轮（R51–R56）在"复现 cybersole"这个目标上的进展是：

- `HbxFlow` 的加购链路 ✅（R52 抓到）
- 五个工具参数 ✅
- BSTN / Goat / Scheels 的端点 ❌

**一个成，三个不成。** 而且这三个的共同点是"入口需要交互，而交互的入口本身需要交互"。

**该换方向了。**
