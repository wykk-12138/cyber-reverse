### 加购抓包：工具造好了，站点还没配合

`NetworkCapture` 加了两个参数：

```
--find-add          列出页面上像"加入购物车"的控件，拿到 CSS 选择器
--click=<css>       点击一个元素，然后等 5 秒，抓它触发的请求
```

设计思路：**购物车端点只会在点击之后出现**，猜它已经让我们错了三次（`hbx` `converse` `bstn`）。
所以不是猜，是点。

`--find-add` 在找不到加购控件时会退化到**列出页面上全部按钮**——
因为"没有加购按钮"通常意味着"按钮藏在尺码选择之后"。

### 实测：两个站都给不出可点的控件

**Goat**：

```
--- add-to-cart candidates ---
[]
```

Goat 是 marketplace：要先选尺码/卖家，"Buy" 才对某个具体报价生效。商品页首屏没有可点的加购。

**HBX**：

```
{"totalButtons": 0, "addish": [], "all": []}
```

**整个页面一个 `<button>` 都没有。**

这比"没找到加购按钮"更值得注意：HBX 的商品页可能

- 用 `<div>` + click handler 而不是 `<button>`
- 或者首屏根本没渲染出购买区（懒加载更深，或者需要登录）

**两种都没到能抓请求的程度。**

### 这一轮的产出是什么

不是"抓到了购物车端点"——**没抓到**。

是**工具**：`--find-add` 和 `--click` 现在能用了。下一个回合只要找到合适的选择器，
一次 `--click` 就能把端点记下来。

**而且 `--find-add` 的输出本身就是证据**：

- Goat 的 `[]` 说明它是 marketplace 模式（无购物车）
- HBX 的 `totalButtons: 0` 说明它的购买区不是标准按钮

这两个结论都不是猜的。
