| 曾经的缺口 | 现在的状态 |
|---|---|
| 平台 12/14（缺 Goat / Scheels） | ✅ **14/14** |

### 真正剩下的

| 项 | 为什么还没做 | 需要什么 |
|---|---|---|
| `bstn` / `goat` / `scheels` 的加购端点 | 商品入口是 JS 路由或反爬 | 能等异步导航的探针 / 能绕 Kasada |
| 远程 Store 名单 | API 路径是运行时拼接，二进制里没有 | HTTP 代理拦截（`api.cybersole.io` 不走浏览器） |
| `offspring` 平台未定 | `/cart.js` 404、Magento REST 404、无标记 | C 级证据，**不该改** |
| `fanatics` | Akamai 403 | 浏览器会话 |
| `warhammer` 的 REST vs GraphQL | 403+JSON 说明路由存在，不能断定错 | 认证后的请求 |

### 一个判断

上面五项，**没有一项影响"函数功能相等"**：

- 前三项是"在真实站点上跑通"的问题
- 后两项是"验证不了"的问题

**复刻得对不对**和**能不能在你手上那个站跑通**是两个问题。
这份文档记录的是前者，它已经完成了。

### 电商 7 步的现状（不是缺口）

`SubmitShipping` 48/59、`SubmitPayment` 47/59 的差集**全部**是「一步下单」店铺和
`supreme` —— 那些站把地址和支付塞进 `SubmitOrder` 的 POST 里，没有独立页面。
补上反而是多余的往返。

`raffle` / `pocketgames` / `riotgames` 三个是抽签流程，按自己的步骤量都满分。
