## 十一、缺口清单（R89–R91 抽查之后）

这份文档的前十节写的是「做到了什么」。这一节写「还差什么」，并且**每一条都标明它属于哪一类**，
因为三类缺口需要的应对完全不同：

| 类 | 含义 | 该做什么 |
|---|---|---|
| **A · 待办** | 代码能解决，只是还没做 | 排期做 |
| **B · 需外部条件** | 需要用户配置、账号、或新工具 | 说清条件，等条件具备 |
| **C · 已知限制** | 已确认在代码范围内解决不了 | 不再投入 |

> **R89–R91 做了一次「手写 flow 抽查」**：七个不是从平台类派生的模块，逐个探测它们的真实端点。
> 结果三处有问题（都已修成诚实失败），四处本来就对。这一节是抽查之后的状态。

---

### A 类 · 待办（代码能解决）

| 项 | 现状 | 差什么 |
|---|---|---|
| `bstn` 的商品卡选择器 | 六轮探测未命中：`div[flex-col]` 和大 `<img>` 都排除了 | 下一层探测：CSS `background-image` |
| `bstn` 的加购端点 | `/cart.js` 404，`/api/beast/geoIP` 200（已验证） | 依赖上一条 |
| `offspring` 的 Hybris 加购 controller | 四个候选全 404，对照 `minibasketAjax` 200 | 依赖过 reCAPTCHA |

**三项，而第二、三项各自依赖第一和外部条件。** 严格说 A 类只有 `bstn` 的商品卡探测是独立的。

### B 类 · 需外部条件

| 项 | 卡在哪 | 需要什么 |
|---|---|---|
| 远程 Store 名单 | `api.cybersole.io` 路径运行时拼接，二进制里没有 | IDA（需重启 DSH）或 HTTP 代理拦截 |
| `offspring` 的交互 | reCAPTCHA 门禁（`recaptcha__z…` 是页面第一个 script） | 用户配打码服务 |
| `offspring` 加购 | 依赖上一条 | 同上 |
| `fanatics` | Akamai Bot Manager 直接 403，无 HTML | Akamai sensor 会话 |
| `scheels` | Kasada 拦直连 | Kasada sensor 会话 |
| `warhammer` 的三条 REST 路径 | 403 是 WAF 无差别拒绝，**不携带路径信息**（R90 的对照实验证明） | 有效账号 |
| `casio` 的结账路径 | AEM + Akamai，四条根相对路径全 404 | 抓 `/{region}/` 前缀下的真实路径 |
| `hbx` 的结账后续 | 加购 API 成功，但前端 mini-cart 不显示，找不到 Checkout 按钮 | 需真实加购后的页面 |
| 效率数字的稳定性 | n=50 已比 n=12 好，但仍是单次测量 | 多轮取中位数 |

### C 类 · 已知限制（不再投入）

| 项 | 为什么解决不了 |
|---|---|
| `OwnTls` 在 `verify.ps1` 里的 WARN | Windows PowerShell 5.1 在此脚本上下文里捕获不到 native exe 输出；手动跑一直是 200 |
| `nike-gs` 的域名 | Nike 没有 kids/SNKRS 子域，GS 按尺码而非主机区分 |
| `hypecommerce` / `bodega` / `livestock` / `nakedcph` / `offthehook` / `premiumgoods` / `shophmvs` | 域名已死或停放 |
| `trophyroom` / `shopify` 的 404 | 通用域名，没有具体站点 |
| `superswipe` 的 `Domains` | 抽签在客户自己的 Shopify 域名上，模块的域名只能是占位 |
| 15 个平台的枚举 | 「平台」是归纳概念，代码里没有对应实体，无法锚定 |

### 抽查结果对照表

| 模块 | 抽查前的记录 | 抽查后 |
|---|---|---|
| `casio` | 71%，四条路径「实现」 | 四条都是 404，已改成诚实失败 |
| `warhammer` | 「403 被拦，路由可能对」 | 403 无差别，三条路径**无任何证据** |

| `riotgames` | 29% | 7/7（尺子不对，R77） |
| `pocketgames` | 29% | 6/6（同上） |

**七个模块，三个有真问题（都修了），四个本来就对。**

### 一个观察：A 类只剩一项是独立的

清单从 R88 的「5 项待办」缩到现在的「3 项，其中 2 项有依赖」。

**这不是因为做了很多，是因为抽查把「以为是待办」的项重新分类了：**
`casio` 移到了 B（要抓 `/{region}/`），`hbx` 移到了 B（要前端状态），
只有 `bstn` 的商品卡探测是真的可以只靠写代码解决。

**A 类缩小是好事**：它意味着剩下的工作里，能靠代码推进的部分确实很少了。
