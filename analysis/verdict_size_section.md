### 尺码字段探针：两个 MISS，两个不同答案

`SizeFieldProbeTests`（`Speed=Slow`）看商品页怎么承载"尺码"。

**HBX —— 页面里根本没有 size。**

```
JSON keys containing 'size': (none)
```

再抓一次网络：商品页只调用

```
GET https://hbx.com/api/v2/shop/countries?limit=999
```

**没有变体 API，没有 SKU 列表请求。** 尺码数据既不在 HTML 里，也不在商品页触发的任何
请求里。

**结论**：HBX 的可选尺码要么在别的入口（列表页把每个尺码当成独立 URL），要么需要登录，
要么这个商品本身没货。**当前证据不支持任何一种，所以不下结论。**

这一点很关键：`(none)` 只能证明"这份响应里没有"，不能证明"这个站点没有"。
要区分得再抓一次尺码可选的商品，那是另一轮的事。

**PopMart —— 有 size 字段，但语义不同。**

```
product_size       商品物理尺寸（cm）
product_product_size
goods_size_title
file_size_exceeds_the_maximum_limit    ← 无关
```

PopMart 是盲盒：**没有"可选尺码"，只有商品本身的尺寸参数**。所以 `size` 字段 MISS
是符合预期的——`PopMartFlow` 用的是"槽位"（slot）而不是尺码，这是对的。

### 同一类探针，三种截然不同的结论

| 站点 | 现象 | 结论 |
|---|---|---|
| HBX | 页面无 size，无变体 API | **未确定**，证据不足 |
| PopMart | 有 `product_size` 但是物理尺寸 | **不需要尺码**，设计如此 |

**这两个在只跑一次正则时输出完全一样（都是 MISS）。**

"探针 MISS" 从来不等于 "实现错"，也可能等于"这个概念在这个站点上不存在"，
或者"这个概念存在但不在这份数据里"。三种情况的处理方式完全不同：

- 实现错 → 改正则
- 概念不存在 → 记录为设计差异，不动
- 不在这份数据里 → 换数据源

### 这一轮没有改代码

查完两个字段，**两处都不该动**：

- HBX 的 MISS 证据不足，改代码只会制造假阳性
- PopMart 的槽位设计是对的

**"查清后确认不用改"和"没查到"是两件事**——前者是结论，后者是欠账。
