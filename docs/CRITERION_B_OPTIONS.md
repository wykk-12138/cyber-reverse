| 事实 | 结论 | 出处 |
|---|---|---|

## 三、三条路径

### 路径 A：改判据 (b) 的口径

把「剩余仅**字符串池中截断**的文案」改成「剩余文案**每条写明为何不可得**」——
去掉"截断"这个预判，因为实测它不成立。

| | |
|---|---|
| **改什么** | `docs/GOAL.md` 里判据 (b) 的一句话 |
| **代价** | 需要 YG 点头（判据是考题） |
| **会带来什么** | 判据与事实一致；(b) 可立即成立（2 条都已写明"缺规则"） |
| **风险** | 判据变松：以后任何"写明了原因"的缺口都算过。**这是真的放宽，不是措辞修正** |

### 路径 B：实现那 2 条的校验行为

按「值必须在本 locale 的 `country` / `state` 名单里」实现，让 `UnknownCountry` / `UnknownState` 有发出路径。

| | |
|---|---|
| **改什么** | `ProfileCsvEditorView` 的 `Validate()` 增加两条规则 |
| **代价** | 不需要 YG 点头（是实现工作），但**规则本身是猜的** |
| **会带来什么** | 2 条文案变成可达；(b) 可能成立 |
| **风险** | **违反证据纪律的"结构对等 ≠ 行为对等"** —— 我实现的是一种**看起来合理但未经证实的**校验规则。原版可能是：只在导入时校验 / 大小写不敏感 / 接受缩写 / 按国家取州（而不是按 locale）。**四个维度都没证据** |

### 路径 C：保持现状，把 2 条记为 Unknown

## 四、我的建议（只是建议）

**路径 C + 等待路径 D 的条件。**

理由：
- 路径 A 是**真的放宽判据**，不是修正措辞。把"截断"换成"写明原因"，等于承认任何有解释的缺口都算过 —— 那样 (b) 就失去了约束力；
- 路径 B 在四个维度全无证据的情况下实现校验，会产生**看起来对但可能全错**的行为。这比不做更危险：它会让 `ProfileCsv` 的测试变绿，而绿的理由是错的。

**但这是 YG 的考题，我按他选的做。**
