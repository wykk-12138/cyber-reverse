# 假数据生成器：**数据全可得，行为全 Unknown**

> 这份文档回答一个具体问题：**复刻件的「Create Test Profile」能不能做成和原版一样？**
>
> **答案分两半**：**数据侧已经全部拿到**（十一轮调查，最后一轮被 ISO 外部验证）；
> **行为侧全部 Unknown**（原版按什么规则组合这些表，一点都不知道）。
>
> 写给下一个要动手的人：**不要再去找数据了，数据在这儿；要找的是那段取数代码。**

### 格式（完整）

```
table   := <name> NUL <u32 body_len + 5> <object>
object  := { value } NUL
value   := 0x02 <name> NUL <u32 n> <n 字节，NUL 收尾>     -- 字符串字段
         | 0x10 <name> NUL <u32 数值>                     -- 整数字段，载荷内联、其后无字节
         | 0x03 <序号> NUL <u32 n> <object>               -- 数组元素，n = 内容 + 4
         | 0x04 <name> NUL <u32 n> <object>               -- 命名的表，n = 内容 + 4
```

## 二、行为侧：全部 Unknown

复刻件现在的实现：

```csharp
private void CreateTestProfile()
{
    group.Profiles.Add(new Profile
    {
        Name = $"test-{group.Profiles.Count + 1}",
        Email = string.Empty,
    });
}
```

**一个名字 + 一个空邮箱。** 原版的数据集能生成完整假档案（姓名/地址/州/邮编/街道/公司/邮箱）。

### 实现它需要的**最小行为证据清单**

以下五条，**没有一条能从数据里读出来** —— 它们都是"怎么用数据"，不是"数据是什么"。

| # | 需要知道的 | 当前状态 | 怎么才能知道 |
|---|---|---|---|
| 1 | **生成哪些字段** | 候选已知：`Profile` 模型有 name / email / firstName / lastName / phone / address1 / address2 / city / state / zip / country / card*（**复刻件源码**） | 已够 —— 按模型的字段填 |
| 2 | **每个字段从哪张表取** | **Unknown**。表名高度暗示（`first_name`→first name、`street`+`building_number`→address1、`postcode`→zip），但"暗示"不是证据 | 反编译取数代码；**这是最可能一次解开的一条** |
| 3 | **是否按国家联动** | **Inference（中）**：中文文案 `{1} 中未知的州/省"{0}"`（R669）说明校验时**知道国家**，即存在国家→州的关系 | 反编译确认；或看 `state` 表是否按国家分段 |
| 4 | **顺序取还是随机取** | **Unknown**。数据集是列表，列表本身不说取法 | 反编译；或运行期连续生成多个 profile 看是否重复/递增 |
| 5 | **一次生成几条** | **Unknown**。按钮文案是 "Create Test Profile"（单数），但不确定是否批量 | 运行期观察一个动作 |

### 为什么这五条不能"从数据推"

**数据里没有"取法"这一层。** 格式解出来的是 `(索引, 值)` 的**集合**；
取法是**代码里的循环与随机数**，它不在 `.rdata` 里，在 `.text` 里。

**这与 R650 记的是同一件事**：那里是"函数属于哪一层"问不出，这里是"字段怎么组合"读不出。
**两次都是：结构可得，行为不可得。**

## 三、解锁条件

| 条件 | 能解开哪几条 | 代价 |
|---|---|---|
| **IDA 库（≥3 GB 空闲内存）** | 第 2/3/4/5 条 —— 取数代码就在生成函数里，反编译一次大概率全见 | 本 session 内存不足，未开 |
| **原版登录凭据** | 第 3/4/5 条 —— 运行期连点两次"Create Test"看结果 | YG 提供 |
| **AOT 元数据格式资料** | **无帮助** —— 它给的是类型/方法结构，不是函数体内的取数逻辑 | 已用掉，不够 |

**第三条要特别说明**：不要再指望"读文档"能解决行为问题。R650 已经证明格式资料给不了"应用层划分"，
这里同理 —— **格式资料描述数据布局，不描述代码逻辑**。

## 四、一句话

> **数据在这儿，取法不在这儿。**

> 十一轮把一片 `.rdata` 从"看不出是什么"做到了"与 ISO 标准逐条对上"。
> 而这一切只证明了**表里有什么**，一个字节也没告诉我**原版怎么用它们**。
>
> **能读数据 ≠ 会用它。中间隔着的是一段代码，而那段代码需要反编译。**
