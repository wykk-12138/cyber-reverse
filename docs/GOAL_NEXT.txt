═══ IDA 每次打开的固定动作（YG 明令，别再忘）═══

IDA 每次启动，GUI 上**至少会弹两个确认框**，不点掉插件就不会起、端口 13337 就不会监听。固定流程：

1) 启动 doctor（带库路径）：
   powershell -NoProfile -ExecutionPolicy Bypass -File "D:\projects\vm2api\.dsh\scripts\ida-mcp-doctor.ps1" -Path "D:\projects\cyber-reverse\target\Cybersole.exe.i64"
   后台跑，因为开 1375 MB 的库要几分钟。

2) **同时/随后用 CUA 读屏点框**，不要只等 doctor 的 180 秒超时：
   mcp__cua__list_windows(app:"ida") → 看到标题是「请确认」的框就 get_window_state 读它 → click 点掉 → **再 list_windows，再读，再点**。
   **规律是至少两个框**，点完还可能出「请稍候...」——那个是进度条，**等，不要点**。
   **判据是"再读一次没有任何对话框"**，不是"点了两次就完"。

3) 已知的两个框（按这个选，别猜）：
   - 「IDA has found an unpacked version of database … It appears IDA did not close properly」
     → 选 **Proceed with unpacked base**（磁盘上那份就是上几轮读成功的那份；退回 packed 会丢掉已建的符号名）
   - 「Database for file '…\Cybersole.exe.id0' is not closed. Do you want IDA to repair it?」
     → 选 **是(Y)**

4) 框清干净后确认就绪（两条都要过）：
   - doctor 输出 `VERDICT: ready`
   - mcp__ida__server_health 返回 status: ok，且带 idb_path / hexrays_ready

5) 如果 doctor 报 `PROXY: MISSING - DSH did not spawn [python -m ida_pro_mcp]` 或端口 REFUSED 且点完框仍在：
   **这是要停下来等 YG 的两类事之一**（DSH 重启 / 开关 MCP 条目）。明确告诉 YG「ida 的 MCP 条目请关一次再开」，不要自己重装或改 YAML。

═══ 每轮固定循环 ═══

① 取一条未结案项：**核心优先**（站点 flow / 风控 solver / 请求指纹），其次类型缺失、类型级缺口，再次名字级，最后截断文案；

═══ 证据纪律（违反即结论作废）═══

Observation 只能来自工具引用的证据；推理标 Inference + 置信度 + 备择解释；
覆盖不全/能力不支持/证据冲突一律显式 Unknown，并写清缺哪类证据；
绝不把"证据不全导致的缺席"当成"行为不存在"或"行为等价"。
结构对等 ≠ 行为对等：只能证明属性存在的成员，行为必须记 Unknown。
复刻件自己写出的 settings/tasks/solvers/checkoutHistory 不得当实机证据。
%APPDATA%\Cybersole 与 %LOCALAPPDATA%\Cybersole 只读。

补充两条（R753/R755 学到）：
- 子串/存在性扫描只能当"该往哪儿看"的地图，不能当判据；命中也不等于被渲染/被调用。
- 活窗口可用时优先用它消歧，但运行中的是 %LOCALAPPDATA% 里的 5.18.35，不是对等目标 5.18.32 —— 每条观测都要标注对象。YG 已说明小版本不动前端。
