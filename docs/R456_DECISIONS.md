# R456 裁决（对 BLOCKERS.md 四问的回答）+ 一条能把卡点 C 直接打开的新线索

> 依据：本会话在 `127.0.0.1:13337`（原版 IDB，`hexrays_ready`，324,901 条字符串）上实测。
> 你那份 BLOCKERS.md 的取证质量很高，四条卡点的描述没有一条是猜的。下面只是裁决 + 一条你可能没试过的路。

---

## 0. 先说新线索：原版里有一张**可解析的绑定描述符表**（卡点 C 的正解）

### 实测

`get_string` 取 R434 那五个地址，拿到的不是短串，而是**拼接在一起的描述符块**：

```
0x143211210 (455 字符) →
  Cybersole.Ui.Views.Monitor.MonitorView,Cybersole.OpenFilter!Setter|
  Cybersole.Global.Settings,Cybersole.Core.MonitorFilters!Getter|
  Cybersole.Global.Settings,Cybersole.Core.MonitorFilters!Setter`
  Cybersole.Models.Flag,Cybersole.Core.Name!Getter`…（共 8 条）
```

用一条容错正则 `([A-Za-z_][\w.`]*\.[A-Za-z_][\w.`]*),([A-Za-z_][\w.`]*\.[A-Za-z_][\w.`]*)!(Getter|Setter)`
在 6 个块里提出 **29 条**描述符，形如：

```
<声明类型全名>,<属性所属类型全名>!<Getter|Setter>
```

### 为什么这条比现有三条路都强

| 来源 | 覆盖 | 缺点 |
|---|---|---|
| `docs/xaml_bindings.json`（174 类型 / 819 成员） | XAML 用到的 | **不含纯 C# 模型**（`Models.Flag` / `MonitorProduct` / `Input` 这些正是你卡点 C 里"职责未定性"的） |
| 字符串池 + locale | 文案 | 被 locale blob 打包，偏移不能 xref（你自己记的障碍 2） |
| IDA 符号 | CRT/编译器 | 业务函数全是 `sub_*` |
| **绑定描述符串（本条）** | **Avalonia 绑定实际查找的那张表** | 需要自己解析（格式已解出，见上正则） |

也就是说：**"哪个类型拥有哪个成员、有没有 setter"这件事，原版是用字符串表直接说出来的**，
不需要伪代码、不需要符号恢复、不需要 Ghidra。

### 建议动作（本轮就能做，成本很低）

1. `find_regex` 分页取**所有**含 `!Getter` / `!Setter` 的字符串（当前 `n=3` 只是第一页），全量 dump 到
   `analysis/binding_descriptors_raw.txt`；
2. 用上面那条正则抽出 `(declaring_type, property_owner, accessor)` 三元组，去重，落到
   `analysis/binding_descriptors.tsv`；
3. 与 `docs/xaml_bindings.json` 求**对称差**：
   - 描述符有、XAML 表没有 → 新增的成员/类型（大概率就是卡点 C 里那 29 个）；
   - XAML 表有、描述符没有 → 可能是 `x:DataType` 或一次性绑定（要单独解释，不要当成"不存在"）；
4. 把「描述符条数 / 与 XAML 表一致数 / 仅描述符有」作为**第五个度量**进 `metrics_report.py`，
   写进 `docs/METRICS.md`。
5. 卡点 C 的 29 个"职责未定性"类型，**先用这张表判一遍**：能判的判，判不了的才留 Unknown，
   并在 Unknown 里写明"描述符表里也没有"还是"有但职责仍不明"。

> 这条属于"现有工具确实不够用"的正当扩展（`bind_diff` / `bind_scope` 都以 `xaml_bindings.json` 为输入），
> 新脚本文件头请照规矩注明理由。

## 1. Q1：为 C7 装 Ghidra —— **不装（维持 R433 裁决 ②）**

### 理由（不是省钱，是方法论）

1. **它解决不了配对问题**：原版 321,244 个函数里 311,203 是 `sub_*`。装 Ghidra 只会把它们改名叫 `FUN_*`，
   **符号不会凭空出现**。配对的前提仍是"知道这个函数是谁"，Ghidra 不提供这个。
2. **它是第三个口径**：我们已有 IDA（Hex-Rays，两条实例）。再加一套反编译器，
   同一段代码会有两种伪代码风格，**差异归因成本立刻翻倍**。
3. **收益只有一条 claim**（C7），而那条 claim 的正确形态不是"任意两函数等价"（永远无法证），
   而是下面这种可判定的拆法。

### 把 C7 拆成三条，两条可做、一条 Unknown

| claim | 内容 | authority | 做法 |
|---|---|---|---|
| **C7a** | 819 个绑定成员中，能在原版定位到**绑定注册点/访问器**的比例 | `tool-evidence` | 用上面那张描述符表 + 访问器（`get_X`/`set_X`）在 IDB 里找同名函数；给比例与清单 |
| **C7b** | 这些成员的**形状**（getter-only / getter+setter / 是否有 setter 副作用）两侧一致 | `tool-evidence` | 描述符表给 `!Getter`/`!Setter`；复刻件侧读 `bind_shape.py`；逐条比 |
| **C7c** | 任意两函数的**伪代码等价** | `unknown` | 缺"符号恢复"（原版 PDB 或调试信息）。**注明 Ghidra 也不能提供**，避免以后再被当成选项 |

> 如果将来真需要"跨函数行为等价"，优先做**行为探针**（同一输入 → 两侧输出/副作用对照），
> 而不是伪代码 diff —— 后者证不了等价，只能证不同。

## 2. Q2：接触正在运行的原版（pid 30328，已登录、最小化）—— **有条件允许，仅只读**

### 允许什么

- **只做一次**：为回答卡点 C（29 个未定性类型）取界面结构；
- 只用 `get_window_state`（UIA 树 + 截图），**不点击、不输入、不悬停触发、不滚轮**；
- 观察完**立刻恢复最小化**（`set_window_frame` 或让它自己回去）；
- 全程**不碰** `%LOCALAPPDATA%\Cybersole` 与 `%APPDATA%\Cybersole` 的写操作。

### 必须同时记录的两件事

1. **那是 5.18.35，不是 5.18.32**（`current\Cybersole.exe`，123.32 MB，`0D98E405E0620AA9`）。
   任何从它得到的界面证据，都要标 `source: live 5.18.35`，与目标版本**分开记**；
   若某条结论只对 5.18.35 成立，必须显式写出来。
2. 若观察期间发现它在**自更新/联网写盘**，立刻停止观察，不要继续。

### 不做

- 不 dump 它的进程内存（那是"接触运行中进程"的更进一步，收益不明、风险明确）；
- 不 hook、不注入、不改它的任何文件。

## 3. Q3：用磁盘上的 `bearer` 让复刻件恢复会话 —— **不做**

### 理由

1. 那是**真实账号的凭证**，拿它让**我们的程序**向厂商服务器发请求，等于用你的身份冒充客户端；
   可能触发风控/封号，且**不可撤销**。
2. **收益对不上风险**：能验证的只是"复刻件的鉴权流程能跑通"，而这条已有单测覆盖
   （`AuthService` 的 `Jwt.Decode` / 过期 / 刷新分支）；它**不能**解决 C7（函数配对），
   也**不能**解决效率对照（那需要跑业务路径，仍然缺凭据且仍然会写原版数据目录）。

### 替代（都能拿到同等证据，且零风险）

| 目的 | 替代做法 |
|---|---|
| 验证登录/刷新/过期逻辑 | 自签 JWT fixture（复刻件自己信任的密钥）—— 已有单测，可补"过期/时钟偏移/刷新竞态"用例 |
| 验证真实响应形状 | 录制响应回放（离线 fixture，不连服务器）；用原版**已有的** `sessions.json`/`settings.json` 结构做 schema 对照 |
| 若 YG 坚持要真链路 | 由 YG 用**测试账号**在隔离机/沙箱里做，不由 agent 代做 |

## 4. Q4：是否"就此交付"—— **不接受整体不可验证，接受分层结账**

objective 三句分开判，**每一句都要给出"达成 / 部分达成（附证据）/ 不可验证（附缺什么、谁能给）"**：

| objective 原文 | 判定 | 依据 |
|---|---|---|
| **函数数量对等** | **可达成**（需先定口径） | 原版 321,244 = 业务 + CRT/编译器/模板实例化；复刻件 AOT 侧 136,798 行符号。要写成"业务面函数数量对照"，并说明分母差异，标 Observation |
| **每个函数功能相等** | **部分达成** | C7a/C7b 可做（描述符表 + 访问器 + 形状对照）；C7c 明确 Unknown |
| **效率相近** | **不可验证**（当前条件下） | 缺原版运行时入口；替代只能给**代理指标**（C15 零调用点比例、复刻件首窗 333 ms），必须标 Inference，不得标测量 |

### 交付物形态

`docs/DELIVERY_STATUS.md` 末尾加一节「objective 三句逐条结账」，格式固定：

```
句 1 函数数量对等 : 部分达成
  证据: <命令> → <数字对照>
  口径: <为什么这样分分母>
  缺口: <若有>
句 2 每个函数功能相等 : 部分达成
  证据: C7a/C7b ...
  Unknown: C7c —— 缺原版符号（PDB / 调试信息），Ghidra 不能提供
句 3 效率相近 : 不可验证
  缺: 原版运行时入口（登录凭据 + 可写数据根）
  代理指标: C15 / 首窗 333 ms（Inference）
```

**goal 不标 complete。** 这一点你的立场是对的，我支持：
a–e 全绿只证明"能证明的都证明了"，不证明"剩下的是对的"。
